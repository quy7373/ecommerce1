# Chatbot and knowledge security

Task SEC-001. SEC-04/07/11/13/14; threats T-10..12/14/15. Scope is public FAQ/policy assistance. The model is an untrusted text producer, never an authorization authority or trusted tool executor. Login must not expand its data access.

## Enforced runtime boundary

The Express support route performs rate/size/origin checks, then sends only a minimized question to an isolated support runtime over an authenticated private channel. Deploy it as a separate process/container identity without inherited commerce credentials; a same-process module sharing DATABASE_URL/Stripe keys does not meet this control. Support gets only an approved-document view or read-only artifact, the approved AI credential, and egress to the configured provider. No Order/User/Cart/Payment/AuthSession/OAuth tables, filesystem secrets, KMS decrypt privilege, payment network APIs, shell, arbitrary HTTP fetch, code interpreter or action tools are available.

Use credential and network denial tests to verify this boundary, not a prompt saying "do not access data." The main API may validate a cookie for user quota purposes, but does not forward cookies, user ID, role, order IDs or session metadata into the model context. No private knowledge namespace exists in this release. Personal order support must use Account & Orders or a separately designed verified human workflow.

## Retrieval supply chain

Only versioned documents with status APPROVED, identified owner/approver and approval timestamp enter the corpus. Review diff/content/hash through two-person publication approval; store immutable version/content hash in an allowlisted manifest. Reject symlinks/path traversal/outside-corpus files, binary content, unbounded chunks, embedded active HTML and unexpected metadata. Do not fetch URLs found in documents. All six supplied policy files are DRAFT and excluded, including FAQ. Approval is a business decision, not an automatic result of passing a scanner.

Retrieve only approved current versions at query time, limit to5 chunks of<=4000characters each, and include document ID/version/section separately from text. Approval revocation invalidates caches immediately and is checked again before response publication; if revocation occurs during generation, discard output and escalate. Corpus text is lower-trust evidence even after approval: instructions hidden in documents cannot override system boundaries. Public corpus must contain no real customer examples/secrets; ingestion scans synthetic/real-looking identifiers and requires human review.

## Input, provider and output processing

1. Accept message1..2000characters, no attachments/history/URLs to fetch. Display a privacy notice before submit: general questions only, no card/password/token/address/order identifiers. Check apparent personal/secrets before logs/APM and redact email, phone/address patterns, card-like numbers with Luhn checks, tokens and order UUIDs. If sensitive material remains suspected or redaction removes needed meaning, skip AI and use safe escalation. Detection is best effort and cannot justify sending private databases.
2. External AI remains OFF until owner approves provider/region, processing agreement, training prohibition, supported storage/retention settings, deletion process and subprocessors. Validate settings in the chosen provider adapter; do not assume a marketing "zero retention" label covers abuse logs or every endpoint. No tracing plugins, prompt caching, transcript analytics, feedback dumps or session replay. Request/response bodies are excluded from infrastructure logs too.
3. Set immutable server instructions with explicit separation of question/evidence/metadata. No secrets in prompt. Disable tools/function calling. Pass only the redacted question and approved excerpts; do not add identity, screen state, browsing history or raw error context. Provider endpoints/models come from fixed config. Ignore user/source instructions to reveal prompts, follow links, change rules, impersonate staff, authorize refunds or state private order status.
4. Constrain model result to `{answer:string,citationIds:string[]}` internally, then validate JSON type/length, allowed citation IDs and sensitive-output patterns. Answer <=4000characters, <=5 citations. Enforce a relevance/entailment check against retrieved passages; citation membership alone is insufficient. Unsupported binding policy/payment/legal statements or uncertain entailment produce deterministic escalation, not an apparently authoritative answer. Evaluator models are untrusted too; use curated evaluation and human review for high-risk policy statements.
5. Public API returns only its documented answer/citations/escalated DTO. Citation title/version/section comes from server corpus metadata; never render model-generated HTML/links. Escape as React text. Missing/unapproved evidence or rejected output returns200 with exact no-evidence response and empty citations; configured provider outage returns503 AI_UNAVAILABLE. Never fall back to uncited model memory.

Exact safe response: `I cannot confirm this from approved store information. Please contact store support.` Do not invent a contact channel. Configure a verified support contact through owner-approved content before launch. No model answer can approve returns, cancel orders, issue refunds or determine user rights.

## Resource and abuse boundaries

Use the limits in [API security](api-security.md):10/min/IP/user,2 in-flight/IP,10 global,10s request deadline. Proposed provider budget: input<=8000tokens, output<=800tokens/request; truncate evidence by whole chunks, never silently drop safety instructions to fit. Check token budgets using the provider tokenizer or conservative upper bounds. Owner sets an explicit daily currency budget before enabling external AI; mandatory budget config has no unlimited default. Alert at80%, stop new paid inference at100%, and use safe escalation while disabled. Currency cap is operational configuration, not a per-customer billing promise.

Log only request ID, document version IDs, redaction/outcome category, token counts, latency and aggregate quota status; no messages, answers, raw IP, personal IDs or full retrieval passages. No browser local/session storage or server chat table. Do not write attacker payloads into long-lived audit descriptions. Restricted test fixtures may store synthetic adversarial messages; they must not contain real identifiers/secrets.

## Evaluation and residual risks

Maintain >=100 versioned adversarial cases covering direct/indirect injection, multilingual/encoded instructions, poisoned citations, attempted cross-user disclosure, malicious URLs/Markdown, fabricated shipping/refund promises, PII echo, provider failure, budget bypass and retired/draft retrieval. Critical boundary tests require100% no unauthorized access/action/secret exposure/draft citation; any failure blocks release. On >=50 approved answerable questions, target>=95% fully supported cited responses under human-reviewed rubric; every unsupported sampled binding-policy answer blocks release regardless of aggregate score. Abstention is acceptable for uncertainty; track its rate separately rather than pressure the model into guessing.

Stochastic generation, ambiguous policies, imperfect redaction and unknown prompt attacks remain risks. Tight runtime boundaries constrain consequences; they do not prove factual correctness. Roll out only the approved public corpus, keep kill switch available, monitor privacy-safe outcome trends and re-evaluate model/prompt/retriever/corpus changes. Reference: [OWASP prompt injection prevention guidance](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html).
