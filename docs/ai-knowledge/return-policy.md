# Return policy

- Document ID: return-policy
- Version: 0.1-draft
- Status: DRAFT — REQUIRES OWNER APPROVAL
- Owner/approver: Unassigned store owner
- Approval date: None
- Retrieval eligibility: EXCLUDED until explicit approval and ingestion

No return window, eligibility rule, exchange entitlement, fee, return address or refund deadline is approved. This draft is a decision framework, not a denial or grant of return rights. Statutory rights must be reviewed for the actual trading jurisdiction before publication.

## Current application capability

The proposed release lets a customer request cancellation only while an order is PENDING_PAYMENT. It does not provide a return authorization, return label, exchange, inspection or refund API. Technical absence of a feature does not establish a no-return/no-refund policy. Do not tell customers that their rights disappear because a button is unavailable.

## Proposed manual review path

For later approval, the owner may adopt a support-led process: receive a request through a verified support channel, verify ownership in an authenticated setting, assess eligibility under approved policy, issue instructions if accepted, record inspection/result, and perform an authorized refund through the payment provider. This sequence is a proposal and must not be offered as an available service yet. There is no approved support address in this repository.

The chatbot must not gather addresses, card information, order identifiers or identity documents to make a return decision. It cannot approve/refuse returns, initiate refunds, access private order data or promise an outcome. It may explain an approved general policy with citations after one exists.

## Required owner decisions

Define whether returns/exchanges are offered; applicable jurisdictions; window start and duration; product-condition/packaging evidence; exclusions; defective/wrong/damaged item handling; authorization requirements; return transport and charges; inspection; refund amount/method/timing; exchanges; abuse controls; and a verified support/return address. Review consumer rights and privacy implications with qualified advisers. Do not fill these gaps with conventional e-commerce assumptions.

## Safe handling while unapproved

For questions such as "Can I return this after 30 days?" the support service must return its no-approved-information escalation response. It must not turn this draft into a rule, assume a default number of days, promise a refund, or direct customers to an invented contact channel.
